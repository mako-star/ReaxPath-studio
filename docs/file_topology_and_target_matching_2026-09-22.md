## 已确认的模块边界：分子式检索，结构由用户选择

2026-09-23 用户明确：目标输入只需要分子式。程序收集符合组成的分子，
识别不同结构并编号，提供给用户查看和选择；用户确定结构之后，才进入后续反应追踪。
这一决定取代上一版要求用户指定拓扑、化学身份或局部模式的多种目标输入设计。

这里“只输入分子式”指目标检索条件；轨迹文件、元素映射等基础数据配置仍由已有分析任务提供。
程序负责按分子式检索和结构整理，用户负责最终选择研究对象。本模块到候选清单为止，
不自动选择目标、不自动启动追踪，也不要求用户预先输入 SMILES/SMARTS 或目标结构文件。

### 处理流程

1. 将用户输入的分子式解析为元素计数字典并规范化，不依赖元素书写顺序。
2. 从逐帧完整分子实例中，找出元素计数完全相同的实例。不能把大分子内部的局部片段
   当作独立分子命中，也不按丰度或寿命默认删除短寿命结构。
3. 根据结构对命中的实例分组。先按元素、原子数、边数、度数等不变量分桶，
   再核对元素标记图同构；原子编号不同不能产生新的结构类别。
   哈希/图指纹只能加速检索，不能代替最终同构验证。实际氢数和连接必须保持。
4. 为不同结构分配易读编号，例如 C2H6O-001、C2H6O-002；另外保存稳定的内部结构键。
   同一结果集内编号不可因排序或展示顺序而改变，跨任务引用时同时保存任务 ID 与结构键。
5. 输出结构候选清单、代表实例和逐帧出现记录，供用户查看后自行选择。

例如 C2H6O 可列出乙醇型和二甲醚型结构，分别编号。编号顺序没有优先级或概率含义。
这里用于分组的图同构是内部整理算法，不是新增的用户输入方式。

### 用户需要看到的内容

每个结构条目至少包含：

- 结构编号、分子式、结构示意图或可用于绘图的图数据。
- 可获得且经过核查的 SMILES，以及化学身份状态；失败或歧义保留说明。
- 首次和最后出现的帧/时间、逐帧数量、出现帧数、代表实例。
- 可回查的 atom_ids、instance_id、frame_id 和源数据引用。

首次至最后出现的跨度不能直接叫作单分子寿命；跨帧实例累计不能叫独立分子总数。
提供这些统计是帮助用户判断，不据此自动替用户选结构。
本轮只约定输出所需信息，不扩展为前端开发任务。

### 结构证据和编号边界

连接图能够区分的结构先按拓扑整理，不要求每个实例先成功生成 SMILES。
如果键型、形式电荷或自由基已得到唯一支持，可附上对应化学身份；不能确定时，
条目明确显示“拓扑已区分，化学身份未决”，并附已有候选。

同一个观测实例可能有多个键型或电子状态解释，这些解释不能当成多个已经在轨迹中
独立出现的异构体，也不能重复计数。它们应留在对应实例/结构条目下供用户查看。
未来若有足够证据区分同一拓扑下的不同化学身份，应保留拓扑层与化学身份层的关联。

仅有 bonds 数据时，不把坐标构象变化、立体异构或自旋状态说成已经得到区分。
当前清单首先提供有数据依据的连接结构差异；结构歧义展示给用户，不强行消除。

### 与反应追踪模块的接口

本模块的结果是结构清单及实例索引。用户后续选择结构编号时，可解析到对应的
结构键、任务、实例集合和原子 ID，作为独立追踪模块的输入。
用户可以继续指定代表实例或时间范围；追踪模块不在本次筛选模块内实现或自动运行。

### 下一步实现与验收

实现范围缩减为：分子式解析与检索、结构分组去重、结构编号、候选清单及实例索引。
复用现有分子实例和化学候选记录，不新增多模式目标输入或自动目标判定流程。

首批验收覆盖：

- 相同分子式的不同连接结构分别编号。
- 相同结构换原子编号、跨帧或出现多份时归入同组，但保留全部实例。
- 图指纹相同仍通过完整图核对，避免误合并。
- 化学身份未决的实例不被丢弃，多种解释不重复计数。
- 分子式无命中返回空清单；非法输入给出清晰错误。
- 编号可追溯到原始帧和原子；生成清单不会触发反应追踪。
